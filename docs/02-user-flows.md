# Flujos principales

## Cliente

Landing → registro/login verificado → elegir problema → detalles/fotos/video → diagnóstico preliminar → dirección → horario → presupuesto revisado → aceptación del presupuesto → asignación → profesional confirmado → pago verificado → visita → cierre técnico → conformidad → historial y reseña opcional.

La aceptación del presupuesto crea el trabajo; un pago nunca crea otro trabajo ni decide su profesional. El regreso de Mercado Pago no confirma un cobro. La visita requiere el pago inicial aprobado en el checkout canónico. El cierre técnico espera conformidad explícita; una reseña no sustituye esa decisión y el silencio no completa el servicio por defecto.

El contrato vinculante de estados, permisos y efectos está en [service-lifecycle.md](architecture/service-lifecycle.md). Las reglas comerciales pendientes D05/D06 no se consideran aprobadas por este documento.

## Profesional

Invitación → onboarding → documentación/herramientas/zonas → revisión → aprobación → solicitudes → aceptar/rechazar → estados → registro de equipo → diagnóstico real → cierre → QR → pagos.

## Admin

Dashboard → invitar/aprobar profesionales → configurar precios/diagnóstico → ver solicitudes → asignar → supervisar trabajos → controlar pagos → calidad/reclamos/garantía → auditoría.
